# Decisions

Choices the spec did not make. `NEEDS CONFIRMATION` items are listed in the phase report.

## Phase 1

- **D1 · Template packages removed.** The project came from the Unity 2D template. Removed packages not on the allowed list (`01-architecture.md` §Packages): 2d.animation, 2d.aseprite, 2d.psdimporter, 2d.spriteshape, 2d.tilemap.extras, 2d.tooling, collab-proxy, learn.iet-framework, timeline, visualscripting, ugui; and the template's `Assets/Welcome` tutorial. Kept the IDE integrations and the 2D sprite/tilemap built-ins (needed by the 2D renderer tooling). Added burst 2.0.0, collections 6.6.0, mathematics 1.4.0, nuget.newtonsoft-json 3.2.2.
- **D2 · Nullable reference types** are enabled through a `csc.rsp` (`-nullable:enable`) next to every HeadLoss asmdef (pure, Unity, editor and test assemblies).
- **D3 · Hand-checked air table.** CoolProp is not installed on this machine, so `fluids/air.json` comes from `tools/fluidtables/handchecked_air.py` (ideal gas, Sutherland viscosity and conductivity, c_p fit), as `06-fluids.md` allows until the end of Phase 2. `tools/fluidtables/generate.py` (CoolProp) is ready; it needs `pip install CoolProp`. **Confirmed:** CoolProp 8.0.0 installed; all fluid tables are now generated by `generate.py` and the hand-checked script is removed. Liquids are evaluated at max(1 bar, 1.05 × saturation pressure) so water stays liquid to 120 °C, and below the triple point they take the 0.01 °C values (freezing is not modelled).
- **D4 · Hand-made layouts** live in `Data/handmade/<id>.json` (not one of the files listed in `01-architecture.md` §Data, which covers generated content).
- **D5 · Fan curve data.** Efficiency `η(x) = η_peak · (1 − ((x − 0.6)/0.6)²)`, `x = Q/Q_max`, peak at 60% of Q_max, with a floor of `0.1 η_peak` at shutoff so input power stays finite. Reverse-flow `K_rev = 5` for every fan; connection diameters (used for K_rev and the initial guess) 125–1000 mm by size. Generated by `tools/equipment/fan_curves.py`.
- **D6 · Vent grille face area** 0.04 m² (200 × 200 mm) for `air-supply-vent`; the grille K 2.0 is referenced to it. **Confirmed.**
- **D7 · Air network elevation.** All air nodes (intake, ducts, vents, rooms) sit at the ceiling-layer elevation; the automatic vertical drop at floor equipment is not modelled, because ambient air head cancels for air at room density. NOTE for Phase 5: the spec's gas elevation term `ρ_link g Δz` uses gauge pressure; for gases the physically correct buoyancy is `(ρ_gas − ρ_air) g Δz` when gauge pressure is referenced to the local atmosphere. **Confirmed:** use `(ρ_gas − ρ_air) g Δz` for gases in Phase 5.
- **D8 · Drawing rules (revised after the Phase 1 review).** One duct per tile until ceiling capacity arrives in Phase 4. Four-way junctions are allowed (`maxNodeDegree` 4): draw from or to a tee, or draw straight across an existing duct to join it. Running along a duct is still an overlap. Intakes and outlets take one duct. Collinear equal-size joints merge automatically. **Dead ends are open ends**: the air discharges into the room through a free-discharge exit loss (`open-end`, K 1.0) and reaches no outlet. A fan at an intake with no duct blows straight into the room the same way.
- **D9 · Fitting K assignment.** Flow direction for fitting K comes from hop distance to the intake. Elbow K goes to the downstream segment. Tees: run K to the straight-through outlet, branch K to the perpendicular outlet (bull-head: branch K to both). Reducer K goes on the smaller segment (contraction 0.2, or Borda expansion `(1 − A₁/A₂)²`). The `intake-entry` K 0.5 goes on the first segment. Tees are always `tee-sharp` in Phase 1; the elbow quality toggle covers elbows only (smooth tees arrive with tier 2 unlocks).
- **D10 · Long-radius elbows in Phase 1.** `elbow-90-long-radius` is tier 2 in the data, but the Phase 1 gate needs the toggle, so it is available in the Phase 1 test house. Tier gating starts with tech unlocks in Phase 3.
- **D11 · Heatmap scale and default.** The building view opens in the velocity heatmap. "Auto-range with fixed anchors" is read as: the scale runs from 0 to the anchor (6 m/s for air) and only grows, in whole 1 m/s steps (`heatmap.autoRangeStep`), when a duct exceeds the anchor. A fixed top end means an improvement always shows as a colour change. The lock button freezes the range. **Confirmed.**
- **D12 · Linear solver.** The default is sparse LDLᵀ with a minimum-degree ordering (leaves peeled first) and a structure cache per topology. `05-simulation.md` allows "sparse Cholesky with AMD ordering". IC(0)-PCG and dense LDLᵀ are kept and tested against each other. IC(0)-PCG needed ~480 iterations per Newton step on dead-end-heavy trees (283 ms for 2,000 segments). Viscosity is evaluated once per link per solve, at the link temperature; the pressure effect is negligible in the game's range. Density still follows the ideal gas law every iteration.
- **D13 · Number formatting.** The UI is English-only, so the app runs with the invariant culture (decimal point everywhere, matching `Core.Units`).
- **D14 · Debug overlay** toggles with `F3` and exists only in the Editor and development builds (`Debug.isDebugBuild`).
- **D15 · Readouts.** Hover shows the readout for what is under the pointer; selection shows the same readout plus actions (size, delete, elbow quality, fan on/off). Vent readouts show the tier's min / ideal / max as information only; zones and pay arrive in Phase 2. Stress shows "from Phase 4".
- **D16 · Box select** (drag on empty space) is included now; `11-ui-visuals-audio.md` lists it under building controls.
- **D17 · Input System test framework.** `Packages/manifest.json` lists `com.unity.inputsystem` under `testables` so PlayMode tests can drive the drawing tool with `InputTestFixture`. No new package.
- **D18 · Airflow vs tier 1 vent requirements.** The small axial fan into the test house delivers 70–300 m³/h per vent, against a tier 1 code max of 60 m³/h. Fine for the Phase 1 physics test; Phase 2 balancing (fan choice, grille size, hand crank) has to address it. **Confirmed: fix in Phase 2.**
- **D19 · Cross fitting.** `cross-sharp` uses the sharp tee's values: run K 0.4 (straight through from upstream), branch K 1.0 (90° turn); a bull-head cross gives branch K to every outlet. The spec has no cross fitting. **Confirmed.**
- **D20 · Zero-flow solves.** When nothing drives the flow (no running fan or pump, no demands, all fixed-pressure nodes at one piezometric head), the solver returns zero flow and hydrostatic pressures directly. Newton's method only halves a `Q|Q|` flow per step on the way to zero, so the relative test never passed, and the session kept showing the last fan-on result ("turning the fan off does nothing; drawing while off never solves"). The convergence test also accepts an absolute change below `zeroFlowThreshold`.
- **D21 · Methane real-gas effects.** CoolProp methane differs from the ideal gas law by up to 1.1% at MP-main pressure (3 bar absolute) and −20 °C, against at most 1% at building-side pressures (the test covers up to 2 bar absolute). Phase 5: use the table density for MP/HP mains. Gas tables are interpolated as ρ·T/p (nearly flat) for accuracy.

## Phase 2

- **D22 · Small axial fan curve (fixes D18). Confirmed.** `small-axial-fan` is now Δp0 30 Pa, Q_max 250 m³/h (07 had 80 Pa / 350 m³/h), same η curve (peak 0.35). With 80 Pa every sensible layout in a tier 1 house pushed every vent past the 60 m³/h code max, so buying the first fan dropped income to 0. Now the starter reference layout gets 63 / 58 / 58 m³/h (one vent just over the code max, two at m ≈ 1.97): one damper trim puts all three into overdelivery. The small house reference gets 44 / 44 / 29 / 41 / 44 m³/h. Set in `tools/equipment/fan_curves.py`.
- **D23 · Electricity price $20 per kW·s. Confirmed.** 13 starts at $5, with a target of 10–25% of gross at the reference layout. Tier 1 fans draw only 2–3 W, so $5 gave 1–2% and no felt sweet spot. Set together with D36 using the balancing report: the small house reference spends 10% of gross on electricity, the test house with the small fan 22%. The 300 Pa inline duct fan as a booster in a tier 1 house draws ~45 W ($0.9/s, more than the house earns) and pushes vents past the code max, so brute force does not pay. Tier 2+ prices are for Phase 3 to tune.
- **D24 · Commit cost is a geometric diff. Confirmed.** Each metre of duct (tile edge), each fitting tile and each equipment slot is compared between the committed state and the design. Only in the design: full price. Only committed: `refundFraction` (50%) back. Replaced in place (larger size, long-radius elbow): the price difference (07 "costs the difference"); cheaper in place: 50% of the difference back. Equipment swaps and moved ducts count as sell + buy.
- **D25 · Operating settings are live. Confirmed (after a round trip at the Phase 2 review).** Fan on/off and damper opening cost nothing and apply at once to the design and to the built part, without a Commit; both are undoable, and one slider drag is one undo step. The variable-speed drive (Phase 3 task 7, `07-equipment.md`) adds a fan speed slider that works the same way.
- **D26 · Inline parts.** Dampers and inline duct fans sit on one tile inside a straight duct (not on a fitting) and split it. Drawing through or from them is blocked. Deleting a duct beside one removes the part with it. An inline fan points away from the intake when placed and can be turned around. An inline fan that is off is a closed valve (05 §2). Damper price scales × D/D_ref like fittings; its K uses the smaller adjacent duct.
- **D27 · An intake without equipment is an open louvre** (outside pressure at the intake node), so an inline fan further along can draw air through it.
- **D28 · Hand-made reference layouts** (`reference` in `Data/handmade/*.json`) stand in for the Phase 3 auto-router: budget cap = 1.6 × their cost, and a test checks they meet every minimum and no code max with the reference equipment. Test house (the Phase 2 starter): hand crank pre-placed, reference at 70% crank ($32.47, cap $51.95). Small house: no equipment, reference small axial fan ($94.28, cap $150.85).
- **D29 · Pre-placed equipment is worth $0** (13: crank "$0 pre-placed in the starter house"), so replacing it refunds nothing.
- **D30 · Prices the spec does not list:** `cross-sharp` $2 (as the tee, D19), 45° elbows as their 90° versions, `intake-entry` / `open-end` / `vent-grille` $0 (part of the opening or outlet).
- **D31 · Theme colour `good` #4E8F68** for overdelivery and online. The palette had only warning and danger.
- **D32 · Undo.** Design edits undo by snapshot of the draft. Commit is not an undo step; undoing past a commit changes the draft only (it then shows as a pending sale). Discard is undoable. Consecutive moves of one damper slider merge into one step.
- **D33 · Reverse flow at a vent delivers nothing** (an inline fan can suck room air back through a vent upstream of it).
- **D34 · Building list instead of a city (Phase 2 only).** There is no city before Phase 3, so `Esc` from a building goes to a list of the hand-made buildings (`game.json → starterBuildings`) with their state and income; every building keeps earning while another is open. The main menu says "New game" rather than "New city". Settings are greyed out until Phase 3 (task 10 there).
- **D35 · Starting wallet $40. Confirmed.** 13 says $30, but the starter's sensible (reference) layout costs $32.47, so a new player could not afford the layout the game is balanced around. With $40 it fits, with $7.53 left for a damper.
- **D36 · Tier 1 base pay $0.05/s per air vent. Confirmed.** 13 says $0.15. The balancing report showed everything paying back about 3× faster than the 13 targets (small house 1.6 min vs 5 min; cranking paid the fan and ducts in 0.8 min vs 2–3 min). At $0.05: small house payback 4.8 min, cranking at full speed pays the small fan and the ducts in 2.3 min, and the whole Phase 2 arc (starter → fan → small house → inline fan) takes roughly 20 minutes. Tiers 2–5 are unchanged until Phase 3 tunes them.
- **D37 · `codes.json` started with the noise code only**, so the requirement sheet's "codes in force" comes from data. The noise rule itself is the vent code max from `outlets.json` until codes are checked in Phase 4.
- **D38 · Toolbox list in `game.json`** (`toolbox.intakeEquipment`, `toolbox.parts`): hand crank and small axial fan at the intake; damper and inline duct fan as parts. The inline duct fan is tier 2 but is one of Phase 2's three fans; tier gating arrives with unlocks in Phase 3 (as D10).
- **D39 · Offline time is measured but not paid yet.** Loading computes the offline seconds (clock-back → 0, capped at 72 h) and logs them; offline earnings are Phase 3 task 8.
- **D40 · Outlet list and vent labels show the design preview** (what is on screen); the status line and the money bar show the built state that earns.
- **D41 · Operating the hand crank:** hold `C` or hold the crank button (each press is also one click). Holding reaches full speed in about 2 s; speed decays with the 4 s time constant.
- **D42 · Sound defaults:** master 0.5 with soft gains (`balancing.audio`); no mute control until the settings screen (Phase 3).
- **D43 · Selection over hover (Phase 2 review).** With something selected, the right panel keeps showing it with its actions while the pointer moves over other things; with nothing selected it shows what is under the pointer. Selected and hovered intakes, outlets and parts get a square outline. Box select draws its rectangle and selects live while dragging.

## Phase 3

- **D44 · Duct sizes unlock by tier (confirmed at the Phase 3 start).** `pipes.json` sizes carry a `tier`: 80–160 mm tier 1, 200–250 mm tier 2, 315–400 mm tier 3, 500 mm tier 4. Pipe sizes are all tier 1 until water arrives.
- **D45 · Hand-made houses are test fixtures (confirmed at the Phase 3 start).** The test house and small house leave the game and stay in `Data/handmade/` for the physics and rule tests. Their hand-drawn reference layouts are gone; the auto-router builds every reference (retires D28). `HandmadeBuildingDef` is now `BuildingLayoutDef`, shared by hand-made and generated layouts.
- **D46 · Which rooms get vents. Confirmed.** The doc says "every room gets air"; 04 lists bedrooms, living rooms, offices and wards. Built as: every occupied room gets at least one supply vent (bedroom, living, kitchen, bathroom, office, shop floor, workshop, lab, ward); halls, corridors, storage and service rooms get none. One vent per 18 m² in living rooms and bedrooms, 14 m² on shop floors, 12 m² in offices (`buildings.json`).
- **D47 · Tier 3–5 plots in Phase 3. Confirmed.** The city places plots of every tier as 03 says, but only tiers 1–2 are generated now (single floor, air only). A tier 3–5 plot shows its type and "arrives in a later update" and cannot be opened yet (`buildings.json → tiers[].available`).
- **D48 · Auto-router details.** The trunk starts with a straight lead-in of 3 tiles from the intake (no branch joins it there), so the source equipment and a trunk damper always fit before the first junction; then it heads for the outlet centroid, and the outlet nearest the tree joins next. Branches prefer to leave their outlet with two straight tiles (room for a damper; soft penalty, dropped if it walls an outlet off). The velocity limits (4 / 2.5 m/s at ideal flow) are upper bounds: when a minimum fails, the fastest duct on the weakest outlet's path grows one size. When the source overpowers the building, proportional balancing adds a trunk damper and branch dampers until every outlet sits in its band ("no code violated"). Those dampers count in the reference cost and so in the budget cap.
- **D49 · Generation placement rules.** Intakes and outlets never sit on a door tile (a one-duct anchor there would wall the next room off), and an intake needs 3 straight tiles inward in its own room. Outlet requirements get one seeded factor (±10%) for min, ideal and max together, each rounded to 5 m³/h, so a tier 2 minimum of 30 can read 25–35.
- **D50 · Starter house.** Type `starter-house`: 8×6 m, a living room and a bedroom with one vent each, hand crank pre-placed, intake within 6 tiles of both vents. The city tries building seeds until the auto-router meets every minimum at 70% crank on the first layout.
- **D51 · City layout choices the spec leaves open.** Plots fill from the centre outward with spread (`orderJitter` 1.0, 40% of frontage tiles skipped), so the core is dense and the outskirts open. Facilities: water plant and heating plant 3×2, gas station and depot 2×2, substations 1×1; the city-wide ones go to a random district (the depot to an industrial one), each on its district's city-edge side and touching a road. Protected sites 1×1–2×2. Historic buildings are 1×1 tiles on streets in the oldest district. City names are built from two seeded parts.
- **D52 · A new game opens in the city view.** The starter house carries a "Start here" label and a soft pulsing outline until it has been online. Hover shows the plot panel (difficulty hint), a click or tap selects the plot (the same panel with an Open button, for mobile), a double-click or Enter opens it, Esc clears the selection and then opens the menu. `Esc` in a building returns to the city (the Phase 2 building list, D34, remains only for test fixtures without a city). The menu says "New city". A new city's seed is random from the clock, the only randomness outside the seeded generators.
- **D53 · Difficulty dots.** 1–5 dots = round(Σ min flow / 120 m³/h + longest intake-to-outlet duct run / 12 m + (floors − 1) + 0.25 × codes in force) (`balancing.difficulty`). The starter house shows 1, small houses 2, family houses 3. Tier 3–5 plots show tier + 1 until their generator exists. Air needs no facility, so the hint says "Air comes from the building's own intake".
- **D54 · Phase 2 saves (v1 → v2).** The hand-made houses are dropped with their committed spending refunded into the wallet; the save gets a new city whose seed is derived from its save time. Generator version 2.
- **D55 · City drawing.** One city tile is 10 m in world space. Roads are drawn as strips with verges (main roads wider and darker) rather than full tiles; plots are flat blocks with a darker south face whose height grows with tier; online blocks are lit with a 4 s breathing glow, offline and unbuilt ones grey, later-tier ones pale. Six soft cloud shadows drift slowly. City zoom 40–520 m (`balancing.camera`).
- **D56 · Duct leakage is on.** 07's leakage model now runs in every duct: each segment leaks `C_L · πDL · p^0.65` into the room, half at each end (a power-law link in the solver, linear below 1 Pa). Unsealed ducts lose a few percent of the air, so Phase 2 numbers shift slightly; sealing (tier 2, `upgrades.json`) cuts it to a quarter.
- **D57 · Variable-speed drive.** An `addon` item in `equipment.json` (tier 2, $250, efficiency × 0.97) fitted to an on/off fan at the intake or inline; bought with the Commit and priced on its own, so fitting it to a built fan charges only the drive. Its speed slider (20–100%, 1% steps) is live and free like a damper (D25), but changes the built fan only once the drive is built. The EC fan has the slider built in. D10 and D38 are retired: the inline duct fan and smooth fittings are tier 2 items now.
- **D58 · Smooth fittings.** The drawing toggle and the per-fitting buttons cover elbows and tees: long-radius elbows and smooth tees (both tier 2); "Upgrade all fittings" does both.
- **D59 · Insulation price. Confirmed.** 13 quotes insulation per metre "at 22 mm, scaled the same way"; for ducts it is scaled from the duct reference diameter (100 mm) with the same exponent, so 13 mm insulation on a 125 mm duct costs +$0.67/m. Sealing is a flat price per metre as written. Insulation only changes the thermal model (task 6).
- **D60 · Tier 2 references use a drive.** Where the building's tier has variable-speed drives, the auto-router fits one to the source and sets its speed to what the outlets need instead of throttling a 300 Pa fan with a trunk damper (the damper stays as the fallback below 20% speed). This is the efficient tier 2 design; the $250 counts in the budget cap.
- **D61 · Tier 2 base pay $0.20 per vent. Confirmed.** 13 says $0.90. With the balancing report on 20 generated tier 2 buildings: mean reference cost $723, payback 6.0 min (target 10), electricity 24% of gross (target 10–25%); at $0.90 payback was 0.7 min. A lower base pay would push electricity above 25%: a tier 2 inline fan needs about 15–30 W whatever the layout. Tier 1 stays at $0.05 (D36): payback 7.2 min, electricity 15%. Tier 3+ untouched until those buildings exist.
- **D62 · Shop and unlock notices.** The shop is a catalogue: items by category and tier with price, stats and unlock condition (the next tier is shown as a preview, later ones only counted). Buying still happens by placing an item and committing. "Compare with placed" simulates an intake fan swap in the open building, and compares ducts and materials by friction per metre at the same flow. An unlock plays the soft chime and shows a short notice. Larger equipment footprints (centrifugal blower 2×1, EC fan 2×2) are not checked against floor space yet; the floor layer arrives in Phase 4.
- **D63 · Room grid details.** The potential is solved as ∇²φ = −q with q the net source, so air flows away from vents (the spec's sign would point it inward). Room balance: a linear room network with door conductance 0.05 m³/s per Pa and facade leakage 4e-4 m³/s per Pa per m² of wall (`balancing.roomGrid`). Jets spread half-strength into the two side cells. Advection samples across rooms only at door cells. Occupants and machines are spread evenly over their room's lower layer. Heavy CO₂ above the outdoor level settles at k_b·(M_CO₂ − M_air)/M_air. Rooms start at 20 °C. Buildings that are not open step every 5 s, covering the elapsed time in sub-steps of 0.4 s (4× the open building's 0.1 s), so they keep real time.
- **D64 · Heatmap modes in Phase 3.** Velocity, temperature and density colour ducts and rooms; pressure and flow rate colour ducts only (rooms stay neutral). Room velocity has its own scale (0–1 m/s, the legend says so). H cycles the room layer (warmer layer, upper, lower). Concentration (with its species picker) arrives with gases in Phase 5 and stress with bursts in Phase 4. Walls now draw above the room heatmap.
- **D65 · Thermal.** Intake air is the outside temperature from the player's local clock. A duct's surroundings are the upper layer of the rooms it runs over, and the heat it gives off warms those cells. Fans add no heat. The flow solve uses the last thermal temperatures (density, viscosity); the auto-router's references stay at 20 °C so budget caps do not change with the time of day.
- **D66 · Burst room grid.** One parallel job per floor (steps 1–7) and a serial job for the stairwell exchange; the room balance runs in managed code shared with the reference. Default float mode, safety checks off in the job. Matches the reference within 1e-3 over 200 steps; a 10-floor 40 × 28 m building steps in just under 2 ms in the Editor (the budget test passes with little margin; a player build is faster).
- **D67 · Offline catch-up in Phase 3.** Each building's built network is solved at steady state (crank 0) every 6 hours of the time away (`offline.climateStepHours`), at the outside temperature of that block's middle hour from the local time of the save. Ducts carry outside air for the whole block (no room grid offline). Income × time is added per block, with electricity always charged and debt rules as in game. Unlocks count the buildings online at the end of the catch-up. The other stops in 12's event timeline (bursts, leaks, repairs, certificates, events) arrive with those systems. The report shows after at least 60 s away; Enter or Esc closes it. With about 55 generated buildings, 72 h takes well under the scaled 2 s budget.
- **D68 · Settings live in `settings.json`, not in the save.** They apply from the main menu, in every profile and across new cities (03 lists settings among what stays when founding a new city), and they are written only when the settings screen closes. Phase 2's `gameState.settings` is left in the save format, unused. Volumes, palette, UI scale (panel scale 80–150%), reduce motion, autosave interval and keys apply at once; a theme change rebuilds the current screen when the settings close. Rebinding covers every keyboard action except Esc (the mouse and wheel stay fixed); overrides are stored as Input System JSON. The dark theme is a full second palette in `game.json → themeDark`.
- **D69 · Steamworks.NET.** Package `com.rlabrecque.steamworks.net` 2025.165.0 from its git URL (allowed from Phase 3 by 01). `SteamService` starts the Steam API when Steam is running (app id from `game.json → steam.appId`, 480 until you have one) and pumps callbacks; without Steam the game plays the same and logs one line. `RestartAppIfNecessary` is off while the id is 480. Playtest builds get `steam_appid.txt` next to the exe from a post-build step; `steam_appid.txt` in the project root serves the Editor. Steam Cloud uses Auto-Cloud with no code: on the Steamworks site set root `WinAppDataLocalLow`, subdirectory `Elevate Studios/Pipe Game/saves` (company name set by the user after the Phase 3 build review), pattern `*`, recursive. The saves folder holds the profile, its backups and `settings.json`. The package's editor script adds the `STEAMWORKS_NET` define when it is missing; it is now set in the project (Standalone) so entering play mode no longer triggers a recompile.
- **D70 · Company name "Elevate Studios"** (set by the user; product name "Pipe Game"). Saves and `settings.json` live in `AppData/LocalLow/Elevate Studios/Pipe Game/saves/` (since the product name became "Head Loss" on 2026-10-30: `.../Elevate Studios/Head Loss/saves/`). Saves from earlier builds stay in the old `DefaultCompany` folder and are not picked up; copy `profile-1.json*` across to continue one (a Phase 2 save then migrates into a new city, D54).

## Phase 4

- **D71 · Water dead ends are capped.** A water pipe ending in nothing carries no flow (plumbing stubs are capped). Air dead ends stay open ends (D8). A burst opens both ends of the burst segment to atmosphere (open-end K 1.0, `balancing.water.openEndK`).
- **D72 · Air ignores elevation between floors** (extends D7): every air node sits at one elevation, because gauge pressure is referenced to the local atmosphere and the outside air column cancels the duct's. Stack effect is not modelled. Water nodes sit at their floor's ceiling layer; taps and the water connection at the floor layer.
- **D73 · Pipe wall thicknesses** (`materials.json → walls`, by outer diameter): PVC 1.5–7.9 mm (about SDR 11), copper 0.7–1.5 mm, steel 2.0–3.6 mm, stainless 1.0–2.0 mm. Internal diameter = OD − 2 × wall; the rating scales p_ref·D_ref/D on the nominal size.
- **D74 · Pipe sizes unlock with water.** Confirmed. 15–54 mm are tier 2 (water's tier), 76 and 108 mm tier 3 (D44 kept them all tier 1 until water arrived).
- **D75 · Prices and settings the spec does not give.** Confirmed. Pressure-reducing valve (water regulator) $60, tier 2, K 2.0 fully open, setpoint 3 bar by default (1–10 bar, 0.1 bar steps). Relief valve $40, tier 2, discharge K 2.0, opens at 5 bar by default (1–25 bar, 0.1 bar steps). `mains-connection` is a free tier 2 item (a bare water opening behaves the same). Pump VSD $600 and pressure tank $350 as 13.
- **D76 · Ceiling capacity.** Confirmed. Within one network a tile still holds one run (a crossing makes a junction, as D8); different networks share a tile while their capacity units fit (default 4). A tile's use per network is its largest segment there; risers use the shaft tile's capacity on every floor they pass. Drawing, resizing and insulating are refused with "Not enough ceiling space here" when a tile would overflow.
- **D77 · Core drilling.** Confirmed. From tier 2 a pipe or duct may cross an interior wall without a door for $20 per crossing per pipe (`building.coreDrillPrice`); tier 1 buildings still cross walls only at doors. Shafts are open to pipes on every side. Columns, stairwells and protected rooms block every layer.
- **D78 · Taps and the water connection** sit on the floor layer and join the ceiling pipe through an automatic 2.4 m drop of the connecting pipe's size: its friction counts, it costs nothing and takes no capacity (04 "automatic vertical drop").
- **D79 · Reference connection pressure** is 85% of the water facility pressure (3.4 bar, `water.referenceConnectionFactor`): the auto-router and fixtures without a city assume it.
- **D80 · Cold water is at 12 °C** (`water.mainsTemperatureC`); no thermal model for cold water yet (the condensation code comes with Phase 6 content).
- **D81 · Relief valves and pressure tanks are teed in:** the line's flow passes a sharp tee's run (K 0.4); a relief valve discharges from the tee to a drain.
- **D82 · Equipment floor space.** Source equipment takes its footprint at its opening: width along the wall, depth inward (turned when that does not fit), shifted along the wall so the opening's tile is covered. It may not cover outlets, door tiles, furniture, columns, other equipment or other openings, and must stay in the opening's room. Pumps go only at water connections, fans at air intakes, panels at the power connection.
- **D83 · Older saves: tier 2+ buildings are rebuilt.** Confirmed. Tier 2 buildings now generate with floors and water, so edits from a Phase 3 save no longer fit. Loading a save from generator 2 refunds what was spent on each tier 2+ building and resets it (lifetime income kept), as D54 did for Phase 2. ### Task 0 · Foundations

- **D144 · Networks are data (`networks.json`). Confirmed by the user (2026-11-07).** `05` §1.5 asks for one graph per fluid system, and `01` lists no file for them. A new data file names each network: its fluid, toolbox name, opening utility, duct or pipe, display units, first tier, whether it is a closed loop, and the size and material the drawing tool starts with (these were hard-coded for water and gas). A network's id is its fluid's id, except the air exhaust (`air-exhaust`, fluid air), so saves, failures and outlets that name a fluid keep working. Items' `fluids` lists match a network or the fluid it carries, so air parts fit the exhaust. `01` is updated. The exhaust's look is confirmed too: a greyer blue (`#8C9DB0`) and a dashed line, so it does not read as the supply. `06` gives it no colour.
- **D145 · Cooling terminals are on the air supply network. Confirmed by the user (2026-11-07).** `05` §1.5 lists a "cooling" graph but says refrigerant lines are inside the equipment, and neither `06` nor `07` has chilled water or a chiller. So a cooling terminal is a supply grille whose delivery is the cooling its air brings, `ṁ · c_p · (T_set − T_supply)`. The aircon, heat pump and AHU coil (task 2) cool that air, and duct insulation keeps it cool.
- **D146 · Heat outlets are rated at the setpoint, not at the room's temperature now. Confirmed by the user (2026-11-07).** `02` says a heating or cooling outlet delivers heat in W. Rated against the live room, a radiator would deliver less the warmer its room got, so a room that is already warm would read short and could take the building offline. Delivery uses the setpoint (heating 20 °C, cooling 24 °C), so pay depends on the network alone. The heat that really enters the room grid uses the room's temperature, which is what the temperature heatmap shows.
- **D147 · Room loads. Confirmed by the user (2026-11-07).** `13` sizes radiators and cooling terminals by "room load" at −5 °C and +32 °C without saying what the load is. Heating: wall loss to the outside, `U_wall · A_ext · (20 °C − T_design)`, × the `cold-climate` factor; the same walls the room grid loses heat through. Internal gains are left out, as in a real heating design. Cooling: walls at +32 °C against 24 °C, plus the sun at its peak through each window, people (sensible) and machines. Ventilation air is not in either load. The setpoints are `climate.heatingSetpointC` and `coolingSetpointC`.
- **D148 · Devices that join networks. Confirmed by the user (2026-11-07).** A water heater, boiler or (later) heat exchanger stands on a room floor and has ports: an anchor in each network it touches, where the player connects pipes. `in` draws from one network the flow its `out` port sends into another; `fuel` draws gas for the heat it makes; `flow` and `return` close a loop through it. The device heats the water passing through toward its setpoint, within its capacity. Both are 2 × 1 tiles. The boiler heats its loop to 70 °C (`07` gives no flow temperature) and an expansion vessel built into it holds the loop at 1.5 bar (`water.heatingFillPressurePa`; `05` has the vessel but no number). Whether a boiler can feed hot water instead (`07`) is decided in task 1.
- **D149 · Coupled solve.** `05` §1.5: a device's child network is solved before its parent (hot before cold, heating before gas), twice over. The parent learns what the device draws, and the child the pressure and temperature at the device's inlet. Networks with no coupled device are solved once. A water heater passes on the mass it sends out, so cold water carries the hot taps' draw at the cold water's density. A boiler draws `Q_gas = P_heat / (η · LHV · ρ_gas)`.
- **D150 · Thermal solve on piped liquids.** It runs with each solve of the network, on the solve's thread, from room temperatures captured when the solve starts. `05` §5 asks for about 1 Hz, and the network re-solves every second anyway. The temperatures go into the next flow solve, so viscosity falls as water warms. Loops start from the last solve's temperatures and, when there is none, from the heater's setpoint; each pass goes round a loop in flow order from the heater's outlet. Building this exposed a fault in the Phase 1 thermal code: a node mixed only the inflows already computed in that pass, so a loop never relaxed. Air networks have no loops, so nothing visible changed.
- **D151 · Temperature reads relative to a setpoint. Confirmed by the user (2026-11-07).** `11` asks for a diverging blue–white–red ramp, colour-blind safe. It is ColorBrewer's RdBu, white at 22 °C (the middle of the 20–24 °C comfort band, so neither a heated nor a cooled room looks off), at least ±10 K and widening evenly. It is a setting ("Temperature vs setpoint"), on by default. With it off, temperature uses the chosen palette as before.
- **D152 · Events and inspections data. Confirmed by the user (2026-11-07).** `events.json` holds `10`'s six events with their durations, effects and rewards. `10` asks for weights but gives none, so every event has weight 1. A new tenant's 24 hours is its duration. Its 30-minute window and 2-hour reward are fields. `13` keeps inspection numbers in `balancing.inspection`, so they stay there, and `inspections.json` holds the inspection kinds and the energy rating bands. The outage numbers are in `balancing.outage`.
- **D153 · A water heater cannot keep a hot tap hot. Decided by the user (2026-11-07): water heaters store hot water in a tank (option 1). Built in task 1.** A hot tap draws 0.10 L/s (`13`). Heating that from 12 °C to 60 °C takes 20 kW, but `07`'s water heater has 3 kW, so it reaches about 19 °C, far below the 55 °C minimum. Even the 24 kW boiler covers about one tap. Real heaters have a storage tank, and real taps do not run all the time. The options were a storage tank, a usage factor on hot-tap flow, or bigger heaters; the user chose the tank. Caveat for task 1: the game's taps draw their design flow all the time, and a tank under a steady draw only delays the cold. So the tank model must give the heater credit for the time between draws (a tank volume, a recovery rate and the draw pattern it assumes). Task 1 proposes the exact model before building it.
- **D154 · Save version 5 and generator version 5.** A building state keeps its networks in one list instead of the `air`, `water` and `gas` fields, and has a list of devices. It is bumped now, before tier 3 radiators exist (task 1), so a save made with a development build between now and task 1 will not be rebuilt when radiators arrive. ### Task 4 · Indoor air quality

- **D155 · The indoor air quality code is in force at tiers 4 and 5. Decided by the user (2026-11-08).** `09` gives the limit (1 000 ppm room mean CO₂) but not the tiers. With `05`'s 0.005 L/s of CO₂ per person and 420 ppm outdoors, each person needs about 62 m³/h of fresh air. A tier 1 bedroom (2 people, one vent with a 60 m³/h maximum) could never pass, and a dining room (0.3 people/m², one vent per 14 m²) needs about 150 m³/h a vent, above every tier's maximum. So it is an advanced code, like Legionella. The tier 4–5 generator must give occupied rooms enough vents for their people, and the router must aim at the rooms' CO₂: both come with tier 4 generation (task 3), where the 200-seed solvability test checks them.
- **D156 · Air outlets cut by the code are a new zone, "CO₂ too high".** Like an isolated outlet, it pays 0 and does not keep the building offline (an operating code). Only outlets that were paying are cut; one below its minimum or above its code maximum keeps that zone. The room goes on the code list as a non-blocking entry, with its air outlets outlined and the fresh air its people need.
- **D157 · CO₂ moves with the mixture's density; it no longer settles out of the air on its own. Decided by the user (2026-11-08).** `05` §3.2 step 7 sank heavy species from the upper layer at `k_b · |ρ_species − ρ_air| / ρ_air` (0.26 /s for CO₂), while the layers mix back at 0.02 /s and ceiling vents freshen only the upper layer. People's CO₂ was trapped low: a 6-person test room heading for 1 042 ppm well mixed was at 4 800 ppm after 12 hours and still rising (lower layer 8 000). This was a fault since Phase 3, only visible on the CO₂ heatmap. CO₂ at room levels does not separate from air; a denser pocket still sinks, because the layer overturn reads the mixture's density, CO₂ included. The same room now settles at 965 ppm in about 4 hours. Natural gas keeps its own rise rule (Phase 5, unchanged). A CO₂ leak in tier 5 should still pool low through the mixture's density; check it in task 7. `05` is updated.
- **D158 · The code reads each room's well-mixed steady state. Decided by the user (2026-11-08).** `09` says "room mean CO₂". The room grid settles within about 10% of the well-mixed value `C = 420 ppm + G / Q` (965 against 1 042 ppm in the test room), and offline only the estimate exists (`12` §Offline catch-up, step 4). So the code reads `C` from each room's built ventilation (its air outlets' flow plus passive vents) the same way in game, offline and in design previews, and a fix pays as soon as it is committed. The heatmap still shows the grid's air, which takes about an hour (V/Q) to catch up. When a building loads, the grid starts at this steady state rather than at outdoor air. The room readout shows the settled value, the fresh air the people need and what they get.

### Task 6 · Inspections and energy rating

- **D159 · The reference's power scales with the cube of delivery. Decided by the user (2026-11-08).** `10` compares against "the auto-router's reference layout power for that building's current delivery". Network by network, the reference's power is multiplied by (the building's delivery ÷ the reference's delivery)³ for flow and heat outlets: the affinity laws on the reference's own ducts. Pressure outlets (taps, stoves) use the power 1.5, since `P ∝ Q³` and `Δp ∝ Q²`. Both exponents are data (`inspection.ratingFlowExponent`, `ratingPressureExponent`). A network that has several kinds of outlet scales by the outlet-weighted mean of their factors. The rating therefore judges how cleanly the air gets there, not how much air the player chose to deliver. Networks the reference runs without electricity (mains pressure, a gas regulator) add nothing, so a pump added there counts against the grade.
- **D160 · Rating details. Confirmed by the user (2026-11-08).** (1) The rating is worked out from a steady solve of what is built (crank at 0, devices at full speed, today's outside temperature), so a fan still spinning up after a Commit does not flatter it. (2) A building is rated when it first comes online after a Commit (old saves: on load), and keeps the grade until the next Commit. (3) A building whose reference uses no electricity is not rated: only the hand-cranked starter house, since a crank draws nothing and any fan would score G. Not rated pays ×1. (4) A building that is not online at steady state is not rated (it delivers nothing to compare). (5) The projected rating in design mode reads the design preview as it is, so it can wobble for a second while a new fan spins up.
- **D161 · Inspection details. Confirmed by the user (2026-11-08).** (1) Inspections start in game only. `12` lists no inspection among the catch-up stops, and a fine the player cannot answer would arrive with the "While you were away" report. A visit in progress, and a fix deadline, pause while the player is away; a pass bonus keeps running (it is a reward, applied analytically, `00` item 5) and its end is a catch-up stop. (2) One visit at a time: no new inspection while a pass bonus runs or findings are open. (3) The inspector checks what is built: every entry on the code list (layout codes, gas room ventilation, indoor air quality) and every outlet above its code maximum. A building with a blocking violation is not online, so in practice a fail means outlets above their code maximum or a room above the CO₂ limit. (4) A building that goes offline while the inspector walks over is not inspected. (5) Findings count as fixed as soon as nothing is found in what is built, checked each second, before or after the deadline. (6) Both fines use the building's potential gross, like the explosion fine, and insurance halves them (`13`). (7) Rolls use their own seeded stream per building, so they do not shift the failure rolls.
